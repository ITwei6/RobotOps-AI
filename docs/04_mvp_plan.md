# MVP 开发计划

## 阶段 1：项目骨架

- 完成项目文档。
- 明确 C++ backend-service 设计。
- 明确 Python agent-service 设计。
- 明确 Web 前端设计。
- 准备样例日志包。
- 暂不写业务代码。

验收：

- `AGENTS.md` 写清项目定位和开发规范。
- `README.md` 能像正式开源项目一样讲清业务闭环。
- `docs/` 覆盖产品、架构、数据模型、MVP、Web 前端设计。
- `CHANGES.md` 记录阶段变更。

## 阶段 2：日志解析

- 扫描日志包目录。
- 识别模块名。
- 解析日志时间、等级、消息。
- 输出结构化日志。

## 阶段 3：Bug 诊断

- 输入 Bug 描述、机器人类型、发生时间、问题模块。
- 根据时间窗口提取日志上下文。
- Agent 生成诊断报告。

## 阶段 4：源码关联

- 根据日志关键句搜索源码。
- 定位函数和调用链。
- 报告中展示源码证据。

## 阶段 5：平台化

- 接入 MySQL。
- 接入 Elasticsearch。
- 增加 Web 诊断工作台。
- 后续接入飞书 Bug。

说明：

- 主前端使用 Web 管理台，不再使用 Qt 作为平台主前端。
- Web 风格参考 `qinshihu/itops-agent-platform` 这类企业运维平台。
- Qt 后续只作为机器人本体调试工具的可选方向，不进入 MVP。

## 阶段 6：售后运维扩展

- 接入机器人侧 collector / gateway。
- 支持机器人资产管理。
- 支持模块心跳和实时状态。
- 支持事件告警。
- 支持售后工单和远程诊断。
